**Auteur:** Sollykhan (Poletti Nikolas)
**Status:** MERGED 2026-09-11 12:04:41Z
**Changements:** +554/-0 (2 fichiers)

**Description:**
Première slice de #44 - infrastructure de manifeste pour versionnage des datasets.

**Fichier `manifest.json` sidecar:**
```json
{
  "schema_version": 1,
  "host_id": "a1b2c3d4e5f6",  // sha256(hostname)[:12]
  "platform": "windows",
  "os_version": "11 24H2",
  "workload_label": "desktop-user",
  "capture_start": "2026-09-11T10:00:00Z",
  "capture_end": "2026-09-11T11:00:00Z",
  "sample_count": 3421,
  "sample_sha256": "…",
  "capturer_ref": "solkapc-run-1",
  "extra": {}
}
```

**Design points:**
- `host_id` = hash (privacy-aware, pas le hostname brut)
- `sample_sha256` verrouille la version du dataset
- `verify_manifest()` re-hash avant training
- UTC normalisé, timestamps avec suffix `Z`
- Totalement découplé du format des samples

**Module créé:**
- `ml/synthaea_ml/data/manifest.py` (260 lignes)
- Fonctions: `write_manifest`, `load_manifest`, `verify_manifest`, `hash_hostname`

**Tests:**
- 17 tests passent (100% coverage des fonctionnalités core)
- Tests de stabilité du hash, round-trip, timezone normalization, etc.

**Review:**
- ✅ Code Python propre avec type hints complets
- ✅ Documentation excellente
- ✅ Gestion d'erreurs appropriée
- ✅ Tests compréhensifs

### 6. PR #176 - Netlink sock_diag Foundation (Issue #92) ⭐
**Auteur:** old-dov
**Status:** MERGED 2026-09-11 12:13:55Z
**Changements:** +744/-0 (7 fichiers)
**Conflit résolu:** `docs/sensors/linux.md`

**Description:**
Première slice de #92 - client `NETLINK_SOCK_DIAG` pour inventaire TCP sockets.

**⭐ PR de qualité exceptionnelle - une des meilleures de la session**

**Crate `sensor-linux-netlink` créé:**

1. **`wire.rs` - Wire protocol encode/decode:**
   - `inet_diag_req_v2` (query envoyée)
   - `inet_diag_msg` (réponses socket)
   - **Endianness correct:** host-order pour la plupart, big-endian pour ports
   - **Tests contre captures réelles** (pas juste round-trip)
   - Aucun transmute `#[repr(C)]` - parsing field-by-field

2. **`socket.rs` - Raw netlink socket (Linux-only):**
   - Opens `AF_NETLINK`/`NETLINK_SOCK_DIAG`
   - Send request, loop recv jusqu'à `NLMSG_DONE`
   - **Loop multi-call load-bearing** (single recv n'a pas retourné DONE empiriquement)
   - SAFETY comments compréhensifs sur chaque unsafe block
   - `OwnedFd` pour cleanup automatique

3. **`proc_join.rs` - inode→PID(s) join:**
   - Scan `/proc/<pid>/fd/*` pour `socket:[<inode>]` symlinks
   - Même technique que `ss`/`lsof`
   - Multi-map (shared listeners across forked workers)
   - `EACCES` traité comme résultat partiel (correct pour unprivileged)

**Vérifié unprivileged:**
- Confirmé empiriquement que sock_diag TCP fonctionne sans root
- Contrairement à conntrack/proc_connector

**Délibérément NON inclus:**
- **conntrack** - attributes TLV-nested, parser plus complexe
- **proc_connector** - sub-protocole distinct
- **UDP sockets** - "listen/established" est terminologie TCP
- **Periodic re-snapshot** - pas de lab VM pour valider
- **Event/Sensor impl** - beacon features + eBPF cross-check nécessitent correlator/tamper wiring

**Tests:**
- 14 tests passent
- Integration tests réels contre kernel
- Test `/proc` scan (pas mocké)

**Review:**
- ✅✅✅ Qualité de code exceptionnelle
- ✅ Wire protocol handling expert
- ✅ Safe syscall wrappers
- ✅ Error handling intelligent
- ✅ Tests réels, pas de mocks
- ✅ Documentation inline excellente
